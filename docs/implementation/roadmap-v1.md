# foxmorrow v1: дорожная карта реализации

Document status: approved
Based on: [foxmorrow v1: дизайн](../design/2026-11-10-foxmorrow-v1-design.md)

Каждый план реализуется отдельным run и имеет свои критерии приёмки. Порядок реализации: 000, 001 (можно параллельно с 000), 003, 002, 004, 005. Номера планов сохраняют порядок дизайна, а не порядок выполнения. Подробные планы 002–005 пишутся после завершения плана 000, на подтверждённых фактах о Devin.

| № | План | Результат | Зависит от | Статус плана |
|---|---|---|---|---|
| 000 | [Этап 0: проба Devin](impl-000-devin-probe.md) | Ответы на вопросы §10 дизайна, ID моделей, fixture `sessions.db` с ролями плагина и проекта | Вход в Devin CLI | готов |
| 001 | [Ядро и CLI](impl-001-core-journal.md) | Cargo workspace, журнал SQLite, `init`, `assign`, `check`, `report`, `status`, правила порядка и неизменяемости, оценка C1–C6 по нормализованному наблюдению, `finalize` в библиотеке | ничего | готов |
| 003 | Роли, профили, брифы | Перенос 21 роли, `roles/roles.json`, `profiles/devin.json` с таблицей семейств, генератор `agents/` с маркером `foxmorrow-role-sha256`, `sync`, проектные роли, проверка skills, шаблоны брифа `en` и `ru`, `assign` без низкоуровневых флагов | 001, результаты 000 | после 000 |
| 002 | Адаптер Devin: доказательства | Карта схемы и reader `sessions.db` → `ChainObservation`, `foxmorrow hook`, CLI `verify` и `finalize`, запись модели и `session_id` root | 001, 003, результаты 000 | после 003 |
| 004 | Skill `fox` и Doc Flow | `skills/fox/SKILL.md`, references, порядок BRD, ADR, PRD, плана, `init --doc` и `init --plan` с проверкой цепочки `Based on` | 001, 003 | после 003 |
| 005 | Дистрибуция | Загрузчики, `checksums.json`, `hooks.json`, манифест плагина, CI-матрица на 5 платформ, выпуск по тегу, README | 002–004 | после 004 |

## Границы между планами

- План 001 не знает о Devin. Оценка утверждений C1–C6 в нём работает с нормализованным наблюдением `ChainObservation`; как его получить из `sessions.db`, решает план 002.
- Флаги `assign` для профиля, ожидаемой модели и хешей в плане 001 низкоуровневые. План 003 вычисляет эти значения сам из каталога ролей и шаблона брифа.
- CLI `verify` и `finalize` появляются в плане 002, когда есть источник наблюдений, а таблица семейств моделей уже создана планом 003. В плане 001 эти функции есть в библиотеке и покрыты тестами.
